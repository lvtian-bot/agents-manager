# 多 Agent 管理插件规划

## 定位

面向同时使用多个 Agent 的人，首版从管理共享指令入手。用户可以把通用要求分发给各 Agent，把 Work、Code 项目规范分发到对应项目；某一端积累了值得共用的改进时，可以审阅差异并收回修改。每个项目保留自己的专属内容。原有的 Obsidian 笔记总结和选区翻译作为配套工具完整保留。两项功能分别注册命令，快捷键由使用者自行设置。

已有 QuickAdd 脚本是行为基准。原知识库中的模型、文献分类、文档路径、Work 和 Code 分组以及目标列表，统一放进由本地用户选择导入的配置。安装通用版后，摘要可用内置提示词，指令同步可新建一个空白方案。

## AI 总结或翻译

| 场景 | 首版设计 |
| --- | --- |
| 有选区 | 翻译选中文字。支持固定目标语言和按源语言切换目标语言两种规则，以兼容中文译英文、其他语言译中文的现有用法。 |
| 无选区 | 总结当前 Markdown 笔记。内置通用总结提示词。可选配置一个笔记属性，将不同属性值映射到各自的库内提示词；缺值或没有匹配时使用默认提示词。 |
| 模型配置 | 用户提供兼容 Chat Completions 的接口地址和模型标识，可指定凭据环境变量名。保留硅基流动和现有模型参数的配置方式。凭据值仅在请求时读取。 |
| 预览和写入 | 流式显示，可编辑结果、替换选区、保留原文并追加或放弃。写入前检查原笔记和选区。关闭预览可取消请求。阅读模式可预览。 |
| 失败反馈 | 为缺少配置、模板找不到、请求超时和接口错误提供定位信息。诊断日志只记录状态，避免记录笔记、响应正文和凭据。 |

## 跨 Agent 共享指令

一个同步方案包含名称、库内源文档、同步范围和本机目标文件列表。用户可以建立多个命名方案，分别用于自己的规则、团队约定或项目模板。源文档由笔记选择器指定，目标文件支持绝对路径和 `~/` 开头的用户目录路径。

| 场景 | 首版设计 |
| --- | --- |
| 同步范围 | 提供「整篇正文」和「第一个一级标题到第二个一级标题前」两种模式。前者可用于用户级指令，后者保留项目自己的章节。首次创建缺失目标时可沿用模板完整正文。 |
| 目标管理 | 按方案分组，一个方案可登记多个目标。保留添加、移除、待处理数量以及打开时优先定位到有待处理项的行为。移除登记时清理对应记录，目标文件仍留在原路径。 |
| 状态判断 | 为每个目标保存源和目标的同步基线。区分初次创建、内容相同可登记基线、已有内容待核对、上次同步后源单侧变化、目标变化、两侧变化、目标丢失以及结构错误。 |
| 分发与回收 | 预览后逐目标操作。保留从源分发、回收目标正文、目标删除后重建、差异行勾选和合并写回。行级合并继续按原脚本默认采纳目标侧的差异行，用户可以逐行调整。 |
| 写回与隔离 | 保留源笔记属性和目标范围之外的内容。优先读取打开编辑器中的最新文本。写入前复核快照并备份，确认所需写入成功后更新基线。一个目标或方案失败时，其余仍可操作。 |

首版采用桌面端，指令同步需要访问库外本机文件。安装和启用只注册命令。通用同步配置默认没有外部目标，用户登记目标后才能执行同步。

## 原工作流导入

1. AI 预设还原现有接口、模型、文献属性映射与三份库内提示词，并保留原翻译方向规则。
2. 将原用户级指令及 Work、Code 类型模板映射到三个命名同步方案。导入预览展示源文档、目标清单及基线匹配结果。六个用户级目标、原项目登记表和两份基线按兼容格式承接。
3. 基线沿用原区块解析、换行归一及哈希规则。只迁移能与原目标和同步范围对应的记录，缺失或不匹配项标为待核对。导入动作只写新插件的配置与状态。
4. 保留旧 QuickAdd 脚本和原登记表供回退。验证新配置后再切换旧命令绑定。原有的闪念捕获及周报、归位流程继续使用各自入口。

配置与同步基线按知识库保存。可分享提示词和方案样例，导出时排除凭据值和仅适用于本机的目标路径。

## 实施与验收顺序

1. 用现有脚本和合成样例建立行为基线。保留当前命令入口，通用实现逐项替换其内部调用。
2. 实现模型、提示词和翻译方向设置。用一个全新的知识库验证内置提示词可用，再用原预设验证三种文献模板、默认回退、流式预览、追加与替换。
3. 实现可配置的同步方案和旧状态导入。用任意命名的源笔记和本机测试文件跑通整篇、区块、回收、冲突合并、备份、异常和移除，再用原布局验证现有登记和基线可接续。
4. 在独立测试库中验收 Obsidian 桌面端。其中同步写入测试使用隔离的本机目录。Windows 先做实机验证，再验证 macOS 和 Linux 的本机路径、文件权限和写入行为。

## 首版之后

后续功能优先解决同时使用多个 Agent 时反复发生的管理问题。可先评估任务交接，例如从一个 Agent 切换到另一个时，是否需要手工重复说明目标、已确认的决定和待办事项。交接任务进展与首版同步长期指令是两种需求，分别评估。
