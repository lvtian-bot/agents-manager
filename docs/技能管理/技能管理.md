# 技能管理

技能管理负责在统一工作区标签页内查看、检查、编辑、分发与更新 Agent 技能。[界面入口](../../src/skills/panel.js)

## 职责与边界

- **覆盖范围**：扫描用户级目录（`~/.agents/skills`）、当前 Obsidian 仓库根目录下的 `.agents/skills`（无需在指令同步中登记，按项目级分发目标处理并与已登记项目按路径去重）及已登记 Work、Code 项目下的 `.agents/skills`；仅识别含 `SKILL.md` 的直接子目录（忽略 `.` 开头目录）。没有技能的仓库或已登记项目不显示。
- **自建与 GitHub 技能划分**：在 `sync/skills-sources.json` 中记录来源，未登记或非 GitHub 来源的技能按自建技能处理。两种类型均可查看 `SKILL.md`。自建技能可编辑，GitHub 技能可更新或修改链接。已有自建技能选择 GitHub 类型时填入来源地址，保存后切换类型。
- **不包含的能力**：不承担外部技能安全审查，不自动创建或删除自建技能，也不直接维护 `agent-skill-management` 的 Markdown 台账文件。
- **分发目标纳入原则**：插件仅管理既无法原生识别 `.agents/skills`、也不支持通过自身配置加载额外技能目录的 Harness（如 Claude Code）；凡原生支持 `.agents/skills` 或支持通过自身配置直接加载该目录的 Harness（如 Codex、OpenClaw，以及通过 `~/.gemini/config/skills.json` 加载的 Antigravity），均直接读取源目录，不纳入插件的软链接分发。

## 当前实现与流程

- **发现与检查**（[模型与检查](../../src/skills/model.js)）：解析 `SKILL.md` frontmatter 的 `name` 与 `description`，并检查 frontmatter 是否闭合、目录名是否符合小写 kebab-case、`name` 是否与目录名一致、是否缺失 `description` 以及是否误带 `agents/openai.yaml`。
- **技能列表**：各仓库共用列宽，技能名称与检查异常入口在同一行，说明与 GitHub 更新状态同行。每个已配置的分发工具占一列，打开开关即建立该技能的链接，关闭即移除链接并保留源文件。整目录链接、冲突或失效时，单元格显示具体状态，失效链接可清理。失效链接清理区位于列表下方，技能目录说明位于固定操作栏的操作记录下方。
- **新建技能**：「新建技能」可选「自建」或「GitHub」。新建自建技能时填写名称并编辑 `SKILL.md`，保存后写入。导入 GitHub 技能时填写来源地址，下载成功后保存文件和上游版本。范围默认当前标签页，也可选择尚无技能的当前库或已登记项目。同名目录会阻止创建。
- **按技能软链接分发**（[链接与撤销](../../src/skills/links.js)）：按单个技能向配置好的 Harness 目录建立指向源技能目录的链接（Windows 使用目录联接 Junction，其他平台使用目录符号链接），支持单技能分发、取消链接、失效链接清理与一键补齐缺失链接。
- **页面内管理分发目标**：各作用域顶部提供「管理分发目标」弹窗入口。用户级目标（默认含 Claude `~/.claude/skills`）仅作用于用户级作用域；项目级目标（默认含 Claude `.claude/skills`）对当前 Obsidian 仓库及所有已登记项目共同生效（界面明确标注），保存时均不删除已有文件或软链接。
- **整目录链接识别与转换**：若 Harness 的目标技能目录本身是指向源目录 `.agents/skills` 的软链接，标记为「整目录已链接」并禁止在其内部写子链接，避免污染源目录；提供「转为逐个链接」动作，确认后原子移除原整目录链接、创建真实目录并逐个建回技能链接。目标路径存在实体目录、普通文件或指向他处的链接时标记为「冲突」，只展示现状，不覆盖也不删除。
- **GitHub 更新检查**（[GitHub 更新](../../src/skills/github.js)）：进入「技能管理」先显示本地列表，再后台查询 GitHub 技能来源路径的最新提交。同一来源的成功结果在当前知识库的设备本地存储中保留，24 小时内可跨页面和重启复用。「检查更新」立即重查全部来源。各行按自身记录的提交判断是否有更新，确认已是最新时禁用「更新」，发现新版时启用并高亮。缺少版本记录或检查失败时使用普通按钮，失败的来源下次进入页面可重试。
- **下载与写入**：点击「更新」时按上游最新提交下载文件，自动排除 `.git/`、`.github/`、`.gitignore`、`node_modules/` 与 `agents/openai.yaml`。更新会清理上游已移除的旧文件，并将本次提交记入 `sync/skills-sources.json`。
- **撤销记录**：与指令同步的撤销槽位隔离，使用 `sync/skills-last-operation.json` 与 `sync/skills-pending-operation.json` 记录最近一次创建、导入、`SKILL.md` 编辑、链接分发或清理、整目录转换及 GitHub 更新。撤销创建或导入时移除本次写入的文件，并恢复相应来源记录。执行「转为逐个链接」的撤销前若目标目录内出现非软链接的真实文件或目录，拒绝撤销以避免误删用户文件。

## 状态归属与技术约束

- 来源记录与技能撤销状态均存放在插件目录的 `sync/` 中。GitHub 技能支持从公开仓库匿名导入、检查和更新。请求遇到限流时提示稍后重试。
- 技能文件与分发链接的写操作通过 `plugin.skillsBusy` 互斥保护。后台版本查询可与本地操作并行，同一来源正在进行的查询由自动检查、手动检查和下载共用。分发目标配置的保存同时接入插件共享配置串行队列，避免与指令同步或设置页并发覆写。操作完成后自动原地刷新当前作用域标签页与滚动位置。
