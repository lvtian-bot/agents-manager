# 技能管理

技能管理负责在统一工作区标签页内查看、检查、编辑、分发与更新 Agent 技能。[界面入口](../../src/skills/panel.js)

## 职责与边界

- **覆盖范围**：扫描用户级目录（`~/.agents/skills`）及已登记 Work、Code 项目下的 `.agents/skills`；仅识别含 `SKILL.md` 的直接子目录（忽略 `.` 开头目录）。没有技能的已登记项目不显示。
- **自建与 GitHub 技能划分**：在 `sync/skills-sources.json` 中记录来源；未登记或非 GitHub 来源的技能按自建技能处理。自建技能支持直接编辑 `SKILL.md`；GitHub 复制技能只提供查看与直接更新，不提供编辑。
- **不包含的能力**：不承担外部技能安全审查，不自动创建或删除自建技能，也不直接维护 `agent-skill-management` 的 Markdown 台账文件。

## 当前实现与流程

- **发现与检查**（[模型与检查](../../src/skills/model.js)）：解析 `SKILL.md` frontmatter 的 `name` 与 `description`，并检查 frontmatter 是否闭合、目录名是否符合小写 kebab-case、`name` 是否与目录名一致、是否缺失 `description` 以及是否误带 `agents/openai.yaml`。
- **按技能软链接分发**（[链接与撤销](../../src/skills/links.js)）：按单个技能向设置中配置的 Harness 目录建立指向源技能目录的链接（Windows 使用目录联接 Junction，其他平台使用目录符号链接），支持单技能分发、取消链接、失效链接清理与一键补齐缺失链接。
- **整目录链接识别与转换**：若 Harness 的目标技能目录本身是指向源目录 `.agents/skills` 的软链接，标记为「整目录已链接」并禁止在其内部写子链接，避免污染源目录；提供「转为逐个链接」动作，确认后原子移除原整目录链接、创建真实目录并逐个建回技能链接。目标路径存在实体目录、普通文件或指向他处的链接时标记为「冲突」，只展示现状，不覆盖也不删除。
- **GitHub 检查与直接更新**（[GitHub 更新](../../src/skills/github.js)）：点击「检查更新」时请求 GitHub Commits API 对比最新提交；点击「更新」时直接按最新 Tree 拉取所需文件（自动排除 `.git/`、`.github/`、`.gitignore`、`node_modules/` 与 `agents/openai.yaml`），写入并清理上游已移除的旧文件，同时更新 `sync/skills-sources.json` 中的 commit 基线。
- **撤销记录**：与指令同步的撤销槽位隔离，使用 `sync/skills-last-operation.json` 与 `sync/skills-pending-operation.json` 记录最近一次 `SKILL.md` 编辑、链接分发/清理、整目录转换和 GitHub 更新的完整快照；执行「转为逐个链接」的撤销前若目标目录内出现非软链接的真实文件或目录，拒绝撤销以避免误删用户文件。

## 状态归属与技术约束

- 来源记录与技能撤销状态均存放在插件目录的 `sync/` 中；可选 GitHub 鉴权凭据仅从设置指定的环境变量读取，不持久化保存。
- 任何写操作通过 `plugin.skillsBusy` 互斥保护；操作完成后自动原地刷新当前作用域标签页与滚动位置。
