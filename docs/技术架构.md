# 技术架构

多 Agent 管理是 Obsidian 桌面插件。主功能在主界面工作区标签页内提供多个 Agent 的指令同步与技能管理，笔记总结和翻译是独立命令。当前构建使用 JavaScript、CommonJS 和 esbuild，将插件代码打包成单个 `main.js`。Obsidian 提供编辑器、工作区标签页、命令、设置页和弹窗，桌面端的 Node.js 文件系统接口用于读写库外目标与软链接。

## 调用与数据归属

插件启动时读取当前库的设置，将已保存的值覆盖到默认配置上，并注册工作区标签页视图。通过左侧工具栏图标或「分发与回收指令」「管理技能」命令打开同一个工作区标签页。命令会切换到对应栏目。指令同步读取源文档、项目登记表和历史哈希，为每个目标算出动作。技能管理扫描用户级、当前 Obsidian 仓库与已登记项目的 `.agents/skills`，结合来源记录与软链接状态生成视图。导入、检查更新和直接更新由用户触发 GitHub 请求。笔记处理读取选区或整篇笔记，根据配置发起模型请求，生成结果只在预览中展示，直到使用者确认写入。

| 数据 | 归属与持久化位置 |
| --- | --- |
| 模型、模板、指令源、用户级目标、技能分发目标、GitHub 凭据变量名 | Obsidian 插件数据文件；凭据仅从指定环境变量读取。 |
| 项目登记、指令基线与技能来源记录 | 插件目录的 `sync/`。首次使用同步目录时校验并复制旧数据，优先沿用原先启用的 `nascence-sync/`。 |
| 用户指令、类型模板、目标文件 | 源笔记留在库内，目标在登记的本机路径。同步区块之外的项目正文需要保留。 |
| 技能源码与分发链接 | 实体位于用户级 `~/.agents/skills`、当前 Obsidian 仓库及已登记项目的 `.agents/skills`；分发链接位于设置的 Harness 技能目录。 |
| 撤销记录 | 插件目录的 `sync/` 内分别保存指令同步与技能管理各自最近一次操作的完整快照，成功后替换上次记录。 |
| 模型输出 | 预览期间位于内存；确认后写入原编辑器。 |

## 构建与验证

在项目根目录运行 `npm ci` 安装锁定依赖，`npm run build` 生成产物，`npm test` 先构建后测试。运行 `npm run test:vault` 可生成用于桌面验收的新测试库。上述命令均不部署到主库。安装包由 `manifest.json` 和生成的 `main.js` 组成。

[自动化测试](../test/plugin.test.cjs)从构建产物注册的真实命令进入，用模拟编辑器、弹窗和模型响应检查行为。同步测试使用临时库，替换用户目录与备份目录，读写合成源文件、项目和基线。

[桌面测试库生成器](../scripts/create-test-vault.mjs)每次创建独立目录，复制构建产物，生成两个类型模板、模拟 Agent 目标和登记表。生成器只准备文件。桌面写入验收要使用样例目标；如需连备份也完全隔离，应使用独立系统用户或临时目录独立的桌面进程。桌面样例的模型接口指向本机保留端口，流式成功响应由自动化测试模拟。
