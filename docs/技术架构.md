# 技术架构

多 Agent 管理是 Obsidian 桌面插件。主功能是同步多个 Agent 的指令，笔记总结和翻译是独立命令。当前构建使用 JavaScript、CommonJS 和 esbuild，将插件代码打包成单个 `main.js`。Obsidian 提供编辑器、命令、设置页和弹窗，桌面端的 Node.js 文件系统接口用于读写库外目标。

## 调用与数据归属

插件启动时读取当前库的设置，将已保存的值覆盖到默认配置上。命令执行时才打开对应模块。指令同步读取源文档、项目登记表和历史哈希，为每个目标算出动作。使用者选择动作后，模块执行写入并更新基线。笔记处理读取选区或整篇笔记，根据配置发起模型请求，生成结果只在预览中展示，直到使用者确认写入。

| 数据 | 归属与持久化位置 |
| --- | --- |
| 模型、模板、指令源、用户级目标 | Obsidian 插件数据文件；凭据仅从指定环境变量读取。 |
| 项目登记和两份同步基线 | 插件目录的 `sync/`。首次打开同步面板时校验并复制旧数据，优先沿用原先启用的 `nascence-sync/`。 |
| 用户指令、类型模板、目标文件 | 源笔记留在库内，目标在登记的本机路径。同步区块之外的项目正文需要保留。 |
| 备份 | 同一目录只保留最近一次同步操作的撤销记录。写入前先持久化本次涉及的原文与预期结果，成功后替换上次记录。 |
| 模型输出 | 预览期间位于内存；确认后写入原编辑器。 |

## 构建与验证

在项目根目录运行 `npm ci` 安装锁定依赖，`npm run build` 生成产物，`npm test` 先构建后测试。运行 `npm run test:vault` 可生成用于桌面验收的新测试库。上述命令均不部署到主库。安装包由 `manifest.json` 和生成的 `main.js` 组成。

[自动化测试](../test/plugin.test.cjs)从构建产物注册的真实命令进入，用模拟编辑器、弹窗和模型响应检查行为。同步测试使用临时库，替换用户目录与备份目录，读写合成源文件、项目和基线。

[桌面测试库生成器](../scripts/create-test-vault.mjs)每次创建独立目录，复制构建产物，生成两个类型模板、模拟 Agent 目标和登记表。生成器只准备文件。桌面写入验收要使用样例目标；如需连备份也完全隔离，应使用独立系统用户或临时目录独立的桌面进程。桌面样例的模型接口指向本机保留端口，流式成功响应由自动化测试模拟。
